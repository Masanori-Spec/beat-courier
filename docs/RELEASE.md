## Native evidence

The actual browser MIDI and receipt are copied unchanged into the native job after checking the tested HTML, input hashes and freshly native-authored source bytes. The positive output is never regenerated by the native harness. Only the three deliberate faults are derived afterward.

The official consumer is Debian 13 Ardour `1:8.12.0+ds-1`; actual version output is `ardour-lua version 8.12.0~ds`. Exact package names, architectures, authenticated APT metadata, byte sizes and SHA-256 values are checked before installation/execution. The [package record](evidence/native/package-pin.json) retains those checks. Upstream 8.12 source pin is `10517bff2b2c7b882b453296a939cf5d03174831`; Debian can carry distribution patches, so no upstream-binary-equality claim is made.

The native Lua API authors synthetic sessions at 48 kHz. The unmodified GUI file-import API reads the real metadata-only MIDI using its tempo-map option. Each of the positive, tempo-fault, meter-fault and shifted-position cases is saved and reopened in a fresh process. All eight processes exit normally with code 0. Independent Python checks every point and 120 actual output-pane readings; all six faulty import/reload results reject the unchanged positive expectation while matching their intended fault exactly.

The source has six tempos and four meters. Source 150 eighth notes/minute becomes 75 quarter notes/minute. The 123-BPM-requested point's source duration is already quantized to native superclocks. MIDI rounds it to 487805 microseconds per quarter. The positive map's quarter 28 stays exact while its clock differs by 272 superclocks, or 17/17640000 second (about 0.964 microsecond). The receipt independently accounts for the rational error; no exact elapsed-time preservation claim is made.

Ardour's strict-less-than lookup reports the prior segment at an exact nonzero boundary. Saved XML fixes the actual point position, and one-tick-after readings prove the new segment. Native import also adds one exact terminal `<import` MusicTime; its quarter field rounds up on fresh reload. Only that fully enumerated output normalization is allowed. Input MusicTimes remain unsupported, including native-resaved imported copies containing that marker.

Successful native logs retain nonfatal GTK/GObject diagnostic messages around closure. The record proves normal exits and map behavior, not error-free logs. No user session, audio hardware or external plugin is used. The single ordinary hide-Dummy preference belongs only to the fresh disposable test profile.

## Earlier findings retained

The initial native compatibility route was accepted in run 37598034673, and production output in run 37601909063. Earlier diagnostic failures exposed accessibility limitations, exact-boundary query behavior and terminal-marker normalization; their original evidence is preserved separately from accepted results.

The first UI run exposed an HTML raw-text tokenization failure caused by embedded parser/comment text and a native `<Script>` element. Worker/sample payloads are now Base64-encoded with exact UTF-8 byte checks and an immediate rendered-start assertion. A later print-test failure came from leaving screen-media emulation active before PDF capture; resetting the override and checking print-only content corrected the harness. Both failed browser artifacts remain identifiable. No failure was silently reclassified as a pass.

The product remains bounded to the documented modern Session 7003, stepped, whole-quarter Ardour 8.12 profile. Other Ardour versions, fractional-quarter export, ramps, BBT resets, media export and arbitrary DAW compatibility are outside the claim.
